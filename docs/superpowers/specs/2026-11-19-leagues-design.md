# Лиги Kill Team · экраны и правила

Лига объединяет существующие турниры в сезон. Игрок открывает своё место и видит, какие выступления его определили. Организатор выбирает зачёты и регламент, привязывает прошедшие этапы и разбирает записи без связи с Реестром.

[Открыть кликабельные экраны](../../../design/leagues/index.html) · [План реализации](../plans/2026-11-19-leagues.md)

## Три решения организатора

1. **Кого учитывать.** «Соло» включает личный зачёт. «Парные» и «Командные» независимо включают соответствующие турниры в зачёт организаций. Можно включить любую непустую комбинацию. Если включены оба зачёта, у каждого своя таблица и свой регламент.
2. **За что начислять очки.** По вашему выбору в каждом зачёте доступны сумма турнирных очков (ТП) и очки за итоговое место. За один ивент организация получает сумму результатов **всех** своих составов. В колонке «Ивенты» этот турнир даёт единицу.
3. **Как разбирать равенства.** Можно скопировать порядок тай-брейков из проведённого турнира при создании лиги или задать собственный порядок. Игрок видит действующие критерии рядом с таблицей.

## Откуда берётся строка участника

- **Соло.** У подтверждённого профиля есть постоянный `userId`. Поле профиля `registerNickname` называется «Никнейм в Реестре», может быть пустым и редактируется. По нему ищут человека и подписывают строку. Связь с постоянной карточкой сохраняется при смене любого из ников. История показывает имя, под которым человек действительно выступал. При пустом реестровом нике профиль уже учитывается по ID и отображается с пометкой «Ник в Реестре не указан».
- **Гость или прокси.** Новое выступление автоматически попадает в таблицу с турнирным именем и пометкой «Требует сверки». Повторный расчёт узнаёт ту же исходную запись. Организатор ищет карточку по реестровому нику и подтверждает привязку. Одинаковый текст у двух людей даёт выбор кандидата. Для постоянного игрока без аккаунта можно создать карточку лиги с подтверждённым реестровым ником и позже связать её с профилем. Исправление ошибочной привязки пересобирает обе строки. Пока есть неподтверждённые личности, в регламенте видна отметка о предварительных местах.
- **Организации.** Источник — `tournament_team_rosters.team_id → player_teams.id`. Название организации читается для показа. Состав, его турнирное название и участники сохраняются в истории. Смена названия, капитана и переход участника в другой клуб сохраняют принадлежность уже сыгранного выступления.
- **Замены внутри одного соло-слота.** В режиме суммы ТП заработанное получает фактически игравший человек по сохранённой стороне матча. В режиме очков за место общие очки одного места по умолчанию получает один подтверждённый получатель. Если за слот играли двое, организатор выбирает получателя, а до выбора приз за место находится «На сверке». Оба реальных участника получают по одному ивенту, если оба сыграли. Каждая проведённая игра и каждое официальное место учитываются однократно.

При замене bye получает занимавший слот в момент фиксации. Для каждого человека SoS считается по итоговым ТП слотов его фактических соперников на этом этапе. Усечённый Бухгольц вычисляется на его собственном списке соперников. Bye не входит в этот список. Два разных гостя, последовательно занявшие один слот, могут иметь одинаковый служебный `resultKey`. Сохранённая сторона игры, например `(tournamentId, matchId, сторона)`, однозначно идентифицирует выступление для проверки. При нехватке доказательств строки объединяет организатор. Если назначен получатель очков за место, у второго игрока остаются его собственные ивент, игровые показатели и пики.

## Как считается лига

**Этапы.** В таблицу входят привязанные турниры с опубликованными итогами. Публичный предстоящий или идущий турнир можно привязать заранее. Он помечен «Ожидает итогов». После официальной публикации его участники и очки добавляются автоматически. Отвязка убирает только вклад этого этапа. Исправление и повторная публикация заменяют прежние цифры. Для старого завершённого этапа с неполным источником показывается причина и действие для организатора. Действительный ноль очков у опубликованного участника даёт один ивент. Регистрация без участия, отмена и черновики очков не дают.

**Основные очки.** «Сумма ТП» берёт опубликованные `matchPoints` соло или `teamTournamentPoints` состава. Если в зачёте присутствуют разные шкалы 2×2/3×3, форма показывает, какие исходные ТП будут складываться. «За место» переводит официальное место каждого игрока или состава по одной шкале зачёта. Предлагаемый начальный шаблон за места 1–4 даёт 10, 8, 6, 4 очка, с 5-го места — 0. Организатор может менять значения. Если источник присвоил одинаковое место нескольким участникам, каждый получает значение для этого места. Ивенты считаются отдельно как число различных учтённых турниров субъекта.

**Тай-брейки.** Копирование создаёт снимок эффективного порядка источника, включая фиксированный порядок WTC Doubles и действующую конфигурацию WTC 3×3. Источник можно одновременно добавить как этап при создании. Новый регламент действует в масштабе лиги. Публикация турнира сохраняет его официальный порядок. «Свой порядок» позволяет выбрать и упорядочить критерии, даже если их не использовал ни один из этапов. Первый критерий применяется только при равенстве основных очков, следующий — внутри всё ещё равной группы. Полное равенство даёт места `1, 1, 3`. Имя и постоянный ID стабилизируют показ внутри общего места.

| Критерий лиги | Правило объединения |
| --- | --- |
| Суммарные VP, разница VP, личные победы, Tac Op | Сумма соответствующих величин из учтённых выступлений. Для организации входят все её составы. Доступность зависит от фактов, которые поддерживает формат. |
| SoS, Бухгольц | Сумма значений по выступлениям внутри этапов. Для WTC Doubles SoS имеет отдельный тип «средний SoS этапа», который суммируется без промежуточного округления. Обычный SoS и средний SoS несовместимы для одного критерия. |
| Личные встречи | При сравнении равной группы соло-игроков заново считаются победы в подтверждённых очных матчах между ними во всех учтённых этапах. Bye и игры против остальных исключены. Готовый `headToHeadWins` отдельного турнира не подходит. |
| Ивенты | Большее число различных турниров выигрывает равенство только тогда, когда организатор выбрал этот критерий. |

Выбор показывает совместимые критерии. Если привязка или импорт приносит несовместимый тип или отсутствующее обязательное значение, предпросмотр называет конкретные турнир и критерий. Организатор может изменить регламент, выбрать другой источник или устранить пробел данных. Отсутствующее значение не подставляется как ноль. Сохранение регламента и состава этапов проходит одной операцией.

**Свой критерий.** Организатор может дать критерию название, выбрать доступный показатель и способ объединения — сумма или лучшее значение за этап. Например, «Лучшие VP за этап» даст Rook 49 и Mira 45. Для организации сначала складываются значения всех её составов **внутри** каждого турнира, затем выбранная операция сравнивает этапы. Направление — большее значение выше. Предпросмотр показывает результат до сохранения.

| Источник порядка | Что имеет определённый смысл при импорте |
| --- | --- |
| Соло, включая сетку | Сохранённый порядок из SoS, усечённого Бухгольца, очных встреч, суммы VP и разницы VP. Для очков за место используется официальное опубликованное место, включая решение организатора. |
| Doubles | Выбранные обычный SoS и сумма VP. `null` разворачивается в SoS → VP. |
| WTC Doubles | Фиксированный порядок «личные победы → средний SoS → сумма VP → Tac Op». Для среднего SoS используется точное значение до отображаемого округления. |
| 3×3, включая классический «Меч и щит» | Явный список выбранных командных критериев. Дефолт `null` означает «личные победы → сумма VP → Tac Op». Пустой список означает отсутствие тай-брейков. Инициализированный в структуре 3×3 ноль SoS не является рассчитанным SoS. |

Старый этап можно восстановить по подтверждённым матчам, если они однозначно задают нужные величины. Официальный порядок берётся из публикации. При недостающем обязательном факте весь этап получает «Требует данных», остальные турниры продолжают определять места лиги. Исправление источника автоматически возвращает этап в зачёт. Для исправной публикации с одним спорным получателем места резервируется только награда этого слота. Сверка личности гостя с достоверными очками также допускает временную строку.

**Предлагаемые права.** Создавать лиги могут пользователи с действующим правом создания турниров. Владелец лиги и администратор платформы меняют регламент, привязки и подтверждения Реестра. Судья отдельного турнира сохраняет права в пределах этого этапа. Зрителю и обычному игроку доступны опубликованные лиги и источники очков.

## Обозначения киллтим

Предлагаемый словарь даёт всем 48 записям текущего `KILL_TEAMS` уникальный код длиной 2–3 знака. Цвет показывает сторону. Значок, полное название и сторона доступны также в раскрытии. В списке видны до двух кодов и кнопка `+N`. Повторные пики одной команды дают один код. Источник — фактический пик в завершённой игре.
