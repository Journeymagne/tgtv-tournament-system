# Русская локализация интерфейса

Дата: 2026-08-22
Базовый коммит: `28c51ba`
Статус: черновик для ревью

## Цель

Добавить в интерфейс вторую локаль (русскую) и переключатель языка, сохранив
английскую версию как эталон. Терминология правил Kill Team при переводе не
меняется, и это проверяется автоматически, а не на глаз.

## Объём

**Входит:** все пользовательские строки клиента — `public/app.js` (7892 строки,
27 render-функций), словари, рантайм `t()`, переключатель языка в UI, глоссарий
защищённых терминов и автотесты.

**Не входит (осознанно):**

- Сообщения об ошибках с сервера. `ValidationError` и `HttpError` из
  `src/domain/validation.js` и `src/api/*` (~235 строк) приходят на клиент
  готовым текстом и показываются через `setMessage(err.message)`. Пользователь
  с русским интерфейсом увидит английскую подсказку при ошибке валидации. Это
  известный компромисс и очевидная точка следующей итерации: серверу
  понадобится отдавать код ошибки вместо текста либо учитывать
  `Accept-Language`.
- SEO-мета, canonical, `robots.txt` и `sitemap.xml` из `src/http/seo.js`.
  Остаются английскими, `hreflang` не добавляется.
- Пользовательский контент (имена игроков, описания турниров в markdown) —
  переводу не подлежит по определению.

## Подтверждённые решения

1. **Язык по умолчанию.** При отсутствии сохранённого выбора — по языку
   браузера: `navigator.language`/`navigator.languages` начинается на `ru` →
   русский, иначе английский. Явный выбор в `localStorage` всегда важнее.
2. **Механизм.** Ключи-идентификаторы (`t("tournaments.standings.title")`), а не
   английский текст в роли ключа. `en.js` остаётся полноценным словарём, а не
   только списком ключей, поэтому глоссарные проверки сравнивают `en[key]` с
   `ru[key]` и не теряют силу.
3. **Граница перевода.** Термины правил Games Workshop и названия отрядов
   остаются английскими. Турнирный слой переводится русскими устоявшимися
   эквивалентами (раунд, таблица, швейцарка, Бухгольц, бай, винрейт).
4. **Проверка терминов.** Глоссарий-файл как источник правды плюс автотесты в
   `test/unit/i18n.test.js`. Ручная вычитка — дополнение к тестам, не замена.

## Архитектура

### Файлы

```
public/i18n/en.js        эталонный словарь
public/i18n/ru.js        русский словарь
public/i18n/glossary.js  PROTECTED / FORBIDDEN / SAME_IN_BOTH
public/i18n.js           рантайм: детект локали, t(), plural(), формат дат
docs/i18n-glossary.md    политика перевода, обоснования, спорные случаи
test/unit/i18n.test.js   семь проверок словарей и глоссария
```

Сборщика в проекте нет, `public/app.js` — классический скрипт без `import`/
`export`. Словари подключаются обычными тегами; `defer` гарантирует порядок
исполнения:

```html
<script src="/i18n/en.js?v=..." defer></script>
<script src="/i18n/ru.js?v=..." defer></script>
<script src="/i18n.js?v=..." defer></script>
<script src="/app.js?v=..." defer></script>
```

Версионный суффикс `?v=` ставится по существующему в `index.html` соглашению и
обновляется вместе с остальными при выкладке.

### Двойное потребление словарей

Словари и глоссарий читаются и браузером, и Node (тесты). Без модульной системы
это решается двумя строками в конце каждого файла:

```js
const TGTV_I18N_RU = { /* ... */ };
if (typeof module !== "undefined") module.exports = TGTV_I18N_RU;
```

В браузере `const` верхнего уровня классического скрипта попадает в глобальную
лексическую область и виден следующим скриптам. В Node срабатывает
`module.exports`, и тест делает `require("../../public/i18n/ru.js")`.

### Структура ключей

Плоская карта с точечными именами. Плоская, а не вложенная: сравнение множеств
ключей в тестах становится однострочным, при этом группировка по экранам
сохраняется порядком строк в файле и комментариями-разделителями.

Пространства имён по экранам: `common`, `nav`, `auth`, `play`, `games`,
`tournaments`, `stats`, `challenge`, `profile`, `feedback`, `admin`.

### Рантайм

```js
function t(key, vars) {
  let value = dict(locale)[key];
  if (value === undefined) value = dict("en")[key];
  if (value === undefined) { warnMissing(key); value = key; }
  return interpolate(value, vars);
}
```

Фолбэк-цепочка `ru[key] → en[key] → key` закрывает главный риск выбранного
подхода: забытый русский ключ даёт корректный английский текст, а не голый
идентификатор на экране. `warnMissing` пишет в `console.warn` вне продакшена.

**Интерполяция** — плейсхолдеры `{name}`: `t("games.count", { n: 5 })`.

**Плюрализация** — `plural(key, n, vars)`. Значение в словаре — объект с
формами, выбор через `Intl.PluralRules(locale)`: для английского `{ one, other }`,
для русского `{ one, few, many, other }`. Нужна как минимум для `${row.games}
games` (`app.js:3425`, `app.js:3455`), `${detail.wins} wins` (`app.js:3455`),
`${size} players` (`app.js:5881`, `app.js:6086`) и `player.games === 1 ? "game"
: "games"` (`app.js:3098`, `app.js:3119`).

**Экранирование.** `t()` не экранирует результат: строки словаря статические и
написаны нами, а подставляемые значения экранируются вызывающим кодом через
существующий `escapeHtml`, как и сейчас. Дисциплину закрепляет тест 6.

**Даты.** `app.js:449` сейчас жёстко использует `Intl.DateTimeFormat("ru", …)`
при английском интерфейсе. Форматирование переводится на текущую локаль.

## Глоссарий

Источник правды — `public/i18n/glossary.js`. Файл лежит рядом со словарями, но в
`index.html` не подключается: он нужен только тестам, браузер его не загружает.

`docs/i18n-glossary.md` содержит политику, обоснования и раздел спорных случаев.
Списки терминов он не дублирует, а ссылается на `glossary.js`, чтобы два
источника не разъезжались.

### PROTECTED — обязаны присутствовать в русской строке дословно

- Термины правил: `Kill Team`, `Approved Ops`, `Crit Op`, `Kill Op`, `Tac Op`,
  `Primary Op`, `VP`, `Killzone`, `Dataslate`.
- `Elo` — имя рейтинговой системы.
- Названия отрядов из `src/domain/kill-teams.js`. Они же — имена файлов в
  `public/kill-team-logos/`, поэтому перевод сломал бы отображение логотипов.
- Названия Tac Ops (`tacOpOptions`, `app.js:190`), Crit Ops (`critOpOptions`,
  `app.js:205`) и килзон (`killzoneOptions`, `app.js:217`).
- `gameSystemOptions` (`Warhammer 40k Kill Team`, `app.js:84`) и `seasons[].name`
  (`2026 Q2 Dataslate`, `app.js:228`).
- `Tabletop Simulator` из `venueModeOptions` (`app.js:237`) — название продукта.

Для трёх таблиц опций запрет не только терминологический, но и технический: эти
значения сохраняются как данные. `killzone` лежит в БД отдельной колонкой
`TEXT` (`src/db/migrations/007_tournament_venue_tables.js:18`), названия Tac Op
попадают в сохранённые результаты игр, и по ним потом группируется статистика в
`renderTacOpWinrates`. Перевод значения разошёлся бы с уже записанными играми и
разбил бы агрегаты.

### DISPUTED — требуют решения при ревью спеки

Все три вынесены в `docs/i18n-glossary.md`. До решения реализация использует
предложенный вариант.

1. **Strength of Schedule** — предлагается «Сила соперников (SoS)»: аббревиатура
   в скобках сохраняет узнаваемость для тех, кто привык к английскому названию.
2. **Classified / Non-Classified** — классификация отрядов в All Kill Team
   Challenge. Это имя собственное фичи проекта, а не термин правил; предлагается
   оставить английским.
3. **Faction** — в этом интерфейсе означает выбранный игроком отряд, а не
   механику правил; предлагается «Фракция».

## Тесты

`test/unit/i18n.test.js`, семь проверок. Тесты не требуют базы и попадают в
`npm run test:unit`.

1. **Полнота ключей.** Множества ключей `en` и `ru` совпадают в обе стороны.
2. **Непустые значения.** Ни одно значение не пустая строка. Плюральные объекты
   содержат все формы, которых требует `Intl.PluralRules` для своей локали:
   две для английского, четыре для русского.
3. **Защищённые термины.** Если `en[key]` содержит термин из PROTECTED, то
   `ru[key]` обязан содержать его дословно и столько же раз. Сравнение с учётом
   регистра; для многословных терминов (`Kill Team`, `Approved Ops`, названия
   отрядов) границы слова проверяются по краям всей фразы, а не каждого слова.
4. **Блэклист неверных переводов.** `ru[key]` не содержит ни одной строки из
   FORBIDDEN: «килл тим», «килл-тим», «убойная команда», «очки победы», «крит
   оп», «критическая операция», «зона убийства». Ловит случаи, где термин попал
   в исходную строку в нижнем регистре или в составе словосочетания и проверка 3
   его не увидела.
5. **Плейсхолдеры.** Набор `{…}` в `ru[key]` совпадает с набором в `en[key]`.
   Потеря `{n}` — самая незаметная поломка перевода: строка выглядит целой, но
   число со страницы исчезает.
6. **HTML-безопасность.** Значения не содержат сырых `<`, а `&` встречается
   только как часть валидной HTML-сущности.
7. **Непереведённые остатки.** Совпадение `ru[key] === en[key]` допустимо
   только если значение целиком состоит из защищённых терминов, чисел и
   пунктуации. Иначе ключ обязан быть в явном списке `SAME_IN_BOTH` с
   комментарием-обоснованием. Это и есть отдельная проверка полноты перевода:
   забытая строка не проходит молча.

Тесты 3, 4 и 7 вместе покрывают требование «проверять терминологию отдельно»:
третий не даёт перевести защищённый термин, четвёртый ловит перевод в обход
дословного совпадения, седьмой не даёт пропустить строку целиком.

## Переключатель языка

Сейчас `.theme-toggle` позиционируется самостоятельно (`position: fixed`,
`top: 14px`, `right: 18px`, `styles.css:913`), и места для второй кнопки рядом с
ним нет. Оба контрола заворачиваются в общий контейнер `.floating-controls` —
flex-строку с тем же фиксированным позиционированием.

- Кнопка 44×44, визуально идентична кнопке темы, с текстовой меткой `RU`/`EN`.
- Метка показывает язык, **на который переключит**, — как кнопка темы, которая
  показывает иконку целевой темы.
- `title` и `aria-label` локализованы («Switch to Russian» / «Переключить на
  английский»).
- По клику: запись в `localStorage` под ключом `tgtv-locale` (зеркалит
  существующий `tgtv-theme`), обновление `document.documentElement.lang`,
  `render()`.
- Логика повторяет `savedThemePreference` / `applyTheme` / `wireThemeToggle`
  (`app.js:7857`), включая `try/catch` вокруг `localStorage` для браузеров с
  заблокированным хранилищем: при недоступном хранилище язык применяется на
  текущую страницу и не сохраняется.

На экранах ≤560px обе кнопки ужимаются до 38×38, а `.topbar { padding-right }`
растёт с 64px до 92px (`styles.css:2973`). Это единственное место в задаче,
которое нужно проверить визуально, а не тестом.

Переключатель доступен на всех экранах, включая форму входа и публичную
страницу турнира, потому что контейнер живёт в `index.html`, а не внутри
`renderShell`.

## Порядок работ

Миграция идёт по одной render-функции за раз. Каждый шаг оставляет приложение
рабочим: отсутствующий русский ключ даёт английский текст, а не поломку.

1. **Каркас.** Рантайм, пустые словари, глоссарий, тесты, переключатель. На
   этом шаге `ru.js` пуст, всё уходит в английский фолбэк, поведение
   приложения не меняется.
2. **Таблицы-константы.** `standingsTiebreakerOptions` с полями `label` и
   `description` (`app.js:55`), `opLabels` (`app.js:89`), `venueModeOptions`
   (`app.js:237`) вычисляются один раз при загрузке файла, поэтому готовые
   строки в них не переживут смену языка: переключение их не перерисует до
   перезагрузки страницы. Они переводятся из «объектов с текстом» в «объекты с
   ключами», а `t()` вызывается в момент рендера. Делается до экранов, иначе
   ошибка размножится по всем вызовам.
3. **Общие хелперы и навигация** — `common.*`, `nav.*`.
4. **Каркас и вход** — `renderShell`, `renderAuth`.
5. **Экраны по одному** — `play`; `games` вместе с `renderResultForm`,
   `renderResultReview`, `renderGameDetail`; `tournaments` вместе с публичной
   страницей, формой участия и турнирными формами результата; `statistics`;
   `challenge`; `profile` и `playerProfile`; `feedback`; `admin` вместе с
   `renderRoundSetupModal`.
6. **Диалоги и сообщения** — 16 вызовов `confirm()` и 10 клиентских
   `setMessage("…")` с литералами.
7. **Финал** — прогон теста на непереведённые остатки, вычитка формулировок на
   единообразие тона, обновление версионных суффиксов `?v=` в `index.html`.

## Риски

- **Пропущенная строка.** Основной риск задачи. Снимается тестом 7: ключ,
  совпадающий в обеих локалях, обязан быть явно оправдан.
- **Строка, не проходящая через `t()`.** Тест 7 её не увидит, потому что она не
  попала в словарь. Снимается пошаговой миграцией по одной render-функции и
  финальным grep-проходом по литералам в `app.js` на шаге 7.
- **Разъезжание длин.** Русский текст в среднем длиннее английского на 10–15%,
  что может ломать вёрстку узких элементов — вкладок, кнопок в строках таблиц,
  заголовков колонок. Проверяется визуально после шага 5 на каждом экране;
  правки — в `styles.css`, без изменения словарей.
- **Смешанный язык при ошибках валидации.** Следствие выбранного объёма, описано
  в разделе «Объём».
