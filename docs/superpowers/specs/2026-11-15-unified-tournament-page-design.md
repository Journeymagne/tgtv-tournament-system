# Единая страница турнира

## Задача

Обычный просмотр и администрирование показывают один турнир по-разному. Пользователь выбрал одну страницу с редактированием на месте: администратор открывает турнир и сразу видит «Изменить».

## Выбранный подход

Единая страница по адресу `/tournaments/:slug`. Вход из списка администрирования и старые ссылки на административную карточку открывают эту же страницу. Создание турнира и список администрирования остаются существующими отдельными экранами.

Рассмотренная альтернатива — одинаковое оформление двух самостоятельных видов — отклонена пользователем: она сохраняет два сценария навигации и возможность повторного расхождения.

## Поведение

- Одинаковые шапка, логотип, название, статус и основные сведения на всех вкладках, включая настройки; одинаковая адаптация к мобильному экрану.
- Общие вкладки сохраняют порядок и названия обычного просмотра: обзор турнира, таблица, матчи, статистика, составы для командного турнира.
- Администратор и назначенный управляющий видят «Изменить». Нажатие открывает существующие настройки прямо на странице турнира, без перехода в раздел администрирования. Права проверяет существующий административный API.
- Для пользователей с правами доступны существующие управление участниками, раундами, столами, меню дополнительных действий и история. Нужные служебные вкладки добавляются к общим, не заменяя их.
- Сохранение, автосохранение, действия с раундами и обновление данных оставляют пользователя на странице этого турнира. Другие пользователи и гости сохраняют доступный им просмотр.
- Старые административные ссылки продолжают работать. Кнопка «Назад» возвращает к предыдущему экрану.

## Реализация и ограничения

Использовать существующие JavaScript-компоненты `public/app.js`, лениво загружаемые административные компоненты `public/admin.js` и стили `public/styles.css`; новых зависимостей и изменений серверной авторизации не требуется. Различия разметки по роли заменить различиями доступных действий. Запросы и обновления должны учитывать текущий турнир и не показывать административные данные после ухода со страницы.

Автоматизированные проверки дополняются регрессиями для общей навигации, прав и редактирования. По AGENTS.md локально их не запускать; результат CI относится только к конкретному опубликованному коммиту. Для локального предпросмотра обязательны локальная БД и вход администратора через игнорируемые файлы `work/`.

## Критерии приемки

Один турнир одинаково выглядит при открытии из обычного списка и администрирования; администратор редактирует его на месте; общие вкладки не исчезают; административные действия сохраняют выбранный турнир и страницу; посетителям без прав недоступны настройки и управление.

## Дополнение: проверка результата из списка матчей

По следующему запросу пользователя у администратора и управляющего турниром рядом с ожидающим подтверждения результатом нужна кнопка «Проверить результат». Она открывает существующий экран подтверждения/отклонения напрямую. Поведение распространяется на одиночные Swiss/олимпийские и все командные форматы, включая Classic и Doubles. Кнопка «Подробнее» и существующий доступ игроков сохраняются; завершённые, отменённые игры и BYE не получают новую кнопку. Сервер применяет существующие права управления турниром и при проверке одиночных результатов, как уже делает для командных.
