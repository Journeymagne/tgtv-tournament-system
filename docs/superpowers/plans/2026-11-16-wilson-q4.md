# Wilson and Q4 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans for inline implementation; request one independent code review before delivery.

**Goal:** Add date-based Q4 statistics, Wilson player ranking and revocable all-time faction achievements, with a local authenticated preview.

**Architecture:** Share Wilson and season helpers through `public/game-data.js`. Derive automatic achievements from eligible published results on read and expose them alongside existing achievement data. Update faction tables and preserve explicit sorting.

**Tech Stack:** Node.js, PostgreSQL, browser JavaScript, existing node:test CI.

**Spec:** `docs/superpowers/specs/2026-11-16-wilson-q4-design.md`.

## Global Constraints

- Do not run automated tests locally. Use CI for automated checks; local visual/page/API checks are required.
- Never deploy production during this task. Keep preview helpers and session material under ignored `work/`.
- Preserve unrelated uncommitted work by using the isolated `codex/wilson-q4-mastery` worktree.
- Thresholds use unrounded scores and all-time published non-mirror results; no minimum sample size.

## Review Focus

- A tournament tagged Q3 with a result on November 9 belongs to Q4, and not both seasons.
- Guests/proxies cannot earn an account's badge or merge into its record.
- Editing, deleting or unpublishing results removes qualifications on the next read.
- A score rounded to 50.0 but actually below 50 must not qualify.
- Sorting selects five players from all candidates; latest games stay limited to the five newest.
