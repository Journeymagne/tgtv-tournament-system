# Проверка почтового релиза 5.1.0

Дата: 1 октября 2026. База сравнения: f6471eb (5.0.5).
Все проверки выполнялись локально на отдельной PostgreSQL 16, порт 55451,
БД kt_email_release_test. Production и пользовательские локальные данные
не использовались.

- Целевой прогон безопасности, HTTP-почты, миграций и локализации: 24/24.
- Финальный целевой прогон почты, обновления схемы, Studio, настройки env
  и локализации: 38/38. Для провайдера использовалась подмена HTTP,
  реальные письма в этих тестах не отправлялись.
- Проверен синтаксис Bash-сценария развёртывания.
- Полный прогон: 983 теста, 966 успешно, 17 сбоев. Один сбой Studio возник
  из-за фиксированного SITE_URL в локальном тестовом env; после очистки
  этой настройки все тесты Studio прошли в финальном целевом прогоне.
- Остальные 16 сбоев воспроизведены на базе f6471eb, извлечённой отдельно,
  с единственным исправлением исторической миграции, необходимым для
  запуска новой БД: сравнение 98 тестов, 82 успешно, те же 16 сбоев.

Полный набор тестов не объявляется зелёным. Существующие ошибки относятся к
фикстурам назначения линий и парингов турниров, ожидаемому тексту ошибки
дублирующего участника, снимку схемы турнира в release-data-isolation,
зависимости teamPairingPhaseLabel в клиентском harness, подписи кнопки
подготовки раунда, защищённому термину VP/названию Classic в переводах
и неподдержанному запросу очистки Studio-комментариев в mock уведомлений.

**Исправление, необходимое для проверки релиза**

Миграция 012 вызывает текущий пересчёт рейтингов. После выхода 5.0.1 его SQL
читает game_participants.is_proxy, добавляемый только миграцией 044.
На чистой БД это мешало выполнению всех последующих миграций.
Пересчёт теперь читает необязательное поле через to_jsonb строки; при его
отсутствии используется false. Существующие proxy-игры сохраняют свой флаг.
Проверка исторической миграции ожидает все ещё не применённые версии,
вместо устаревшего единственного номера 40.

**Проверенные почтовые свойства**

Одноразовые и истёкшие ссылки; хеширование токенов и шифрование очереди;
непопадание адреса в общий session API и чужой профиль; одинаковый ответ
восстановления для отсутствующего адреса; смена пароля и завершение сеансов;
сохранение старого email до подтверждения нового; лимит повторной отправки;
лимит ошибочных запросов вне откатываемой транзакции; проверка Origin;
подпись и дедупликация webhook; подавление доставки после bounce;
повтор после 503 с тем же Idempotency-Key и удаление payload после отправки;
применение 042 поверх 045 без изменений пользователей и журнала старых миграций;
сохранение параметров БД при добавлении почтовых переменных.

Реальная доставка, включение Resend webhook и production-проверки выполняются
после разрешённого запуска серверного сценария. Этот файл фиксирует проверки
перед публикацией релиза, а не утверждает, что production уже обновлён.

## Обновление оформления 5.1.1

Перед слиянием выполнены 28 целевых проверок, все прошли: безопасность
почты и экранирование имени с фирменным логотипом, HTTP-сценарии, миграции,
сохранение env, общие маршруты и настройки темы/языка. База та же отдельная
локальная `kt_email_release_test`; предпросмотр работает на другой базе
`kt_email_design_preview`. Синтаксис нового Bash-установщика проверен.

В браузере просмотрены десять состояний страницы почты в обеих темах
при ширине 1366 и 375 px, отдельно состояния успеха и ошибки. Проверены
переключение языка, сохранение ввода при смене темы, удаление токена из адреса,
сохранение токена в памяти и состояние шапки после сброса. Формы Tournament
и Studio сохраняют общую палитру и логотип. Ошибок JavaScript и горизонтальной
прокрутки не обнаружено. Ответы API для отдельных визуальных состояний
подменялись только в локальном браузере; backend-поведение проверялось
отдельным целевым набором.

Три образца новых писем с логотипом доставлены в согласованный Gmail-ящик
во «Входящие». Они отмечены «Тест дизайна», не меняют аккаунт и пароль.
Полный набор повторно не запускался: его известные ошибки описаны выше.
