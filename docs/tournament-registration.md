# Лимит регистраций и оплата

- Необязательный `registrationLimit` задаётся при создании турнира и редактируется до старта. Пустое поле снимает дополнительное ограничение; встроенные ограничения формата остаются: размер сетки single elimination и 128 составов для командного турнира.
- Для личного турнира считаются участники, для командного — составы. Снятые и удалённые заявки место не занимают. Лимит виден на карточке турнира и его странице в формате «зарегистрировано / максимум».
- Проверка действует для самостоятельной регистрации, административного и массового добавления. Блокировка строки турнира сериализует конкурирующие регистрации. Нельзя снизить лимит ниже уже занятого числа мест.
- Во вкладке администрирования «Участники»/«Составы» чекбокс «Оплатил» сохраняется сразу. При ошибке значение возвращается к прежнему; подтверждение сохранения показано рядом. Отметка не влияет на посев, паринги, результаты и доступность регистрации.
- Изменять оплату может только администратор, в том числе после завершения турнира. Изменения записываются в аудит. Публичные страницы участников, составов и команд не показывают оплату.
- Миграция 028 добавляет лимит и две отметки оплаты; существующим турнирам лимит не назначается, оплату по умолчанию никто не имеет. Демо-данные не добавляются.
- Общий форматтер времени использует цикл `h23`: от `00:00` до `23:59`, без AM/PM, независимо от языка интерфейса. Часовой пояс пользователя сохраняется.

API оплаты: `PATCH /api/admin/tournaments/:id/participants/:participantId/payment` или `PATCH /api/admin/tournaments/:id/rosters/:rosterId/payment`, тело `{ "paid": true }` / `{ "paid": false }`.
