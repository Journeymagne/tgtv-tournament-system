# Внедрение ролей и администрирования

28 сентября 2026. Реализована модель доступа и первая рабочая версия интерфейса из [целевой спецификации](roles-and-administration-design.md).

## Реализовано

- Супер-администратор привязан к постоянному ID аккаунта в `platform_ownership`. Обычная регистрация всегда создаёт игрока; публичный `setup-admin` отключён. Другие администраторы не могут изменять привилегии, удалять, блокировать или сбрасывать пароль владельца и других администраторов.
- Организатор — единственный владелец своего турнира (`owner_user_id`). Назначает и снимает судей, может ограничить срок назначения.
- Судья управляет проведением назначенного турнира: настройки, участники и составы, оплата, столы, паринги, раунды, результаты, итоги и экспорт. Назначение судей ему недоступно.
- Администратор платформы автоматически получает права судьи во всех турнирах. Управляет назначениями только в собственных турнирах. Супер-администратор управляет назначениями везде и может передать турнир другому организатору.
- Разрешение создавать турниры выдаётся игроку отдельно, без глобального административного доступа.
- Права проверяются сервером для конкретного турнира; отзыв и срок действия учитываются в существующих сессиях. Сохраняются ограничения состояний турнира и действующие правила результатов.
- Четыре вкладки общего раздела: **Обзор / Турниры / Игроки и команды / Контент**. Организатору и судье доступны первые две.
- Административные экраны доступны через общий раздел «Администрирование»: игровые сессии и обращения — из обзора; аккаунты и команды — из «Игроки и команды»; документация и достижения — из «Контент»; проведение турниров — из «Турниры». Studio сохраняет собственное администрирование.
- В обычных разделах отсутствуют вкладки пользователей и сессий, административное редактирование игр, турниров, чужих команд, достижений и документации. Действия участника, капитана и руководителя своей команды сохранены. Вложенные административные страницы используют адреса `#/administration/...`, сохраняют активный пункт меню и ссылку возврата; старые административные адреса перенаправляются в этот раздел.
- Четыре вкладки внутри турнира: **Обзор / Участники и составы / Раунды / Настройки**. Столы и команда проведения находятся в настройках. История открывается отдельной кнопкой.
- Карточка игрока: роли, разрешение создания турниров, временная блокировка, сброс пароля. Ручной рейтинг и удаление аккаунта доступны супер-администратору. Изменения аккаунтов записываются в общий журнал; назначения судей — в историю турнира.
- Управление Studio остаётся внутри Studio. Турнирные назначения не превращаются в глобальный `isAdmin` и не открывают чужие приватные проекты.

## Первоначальное назначение владельца

После применения миграций выбрать ID существующего аккаунта и выполнить из корня проекта:

```powershell
node scripts/set-platform-owner.js <user-id>
```

Команда не позволяет заменить уже назначенного владельца другим ID. Для изменения имени аккаунта повторное назначение не требуется. Глобальные администраторы, существовавшие до миграции, сохраняют свою роль; никто из них не становится владельцем автоматически.

- `LocalPreviewAdmin` — локальный владелец. Открытие и обновление адреса автоматически использует обычную сессию этого аккаунта.
- Демонстрационный турнир: «Демо · роли и судьи». Организатор — `Preview Organizer`, назначенный судья — `Preview Judge`, автоматический судья — `Preview Platform Admin`.
- Автовход, материалы сессий, PID и логи находятся только в игнорируемом `work/`. Код аутентификации сервера не содержит обхода для preview. Локальный launcher проверяет адрес и имя отдельной базы, использует отдельное имя cookie для совместимости с приложением на порту 3000.

Запуск из рабочей копии после остановки:

```powershell
node work/roles-preview-server.cjs
```

## Проверка

Перед выпуском **4.9.2** полный набор из **928 тестов** прошёл на отдельной локальной базе: модульные, интеграционные, миграции и защита от переноса демонстрационных данных.

При первоначальном внедрении ролей полный набор из 922 тестов прошёл на отдельной базе `tgtv_roles_test_20260928`. Добавлены HTTP-проверки изоляции турниров, назначения и отзыва судей, истечения доступа, автоматических прав администратора, защиты владельца, передачи турнира, оплаты и работы с раундами. Старые тестовые администраторы теперь назначаются явно.

После переноса административных действий в общий раздел прошли 634 проверки: все модульные тесты и HTTP-тесты ролей и переименования составов. Дополнительно браузером проверены административные ссылки, обновление вложенных страниц, обычные страницы без административных кнопок, четыре служебные роли и мобильная ширина. Модульные тесты подтверждают сохранение действий игрока и капитана.

Браузером проверены четыре роли, видимость вкладок и назначения судей, карточка игрока, настольная и мобильная ширина. `/` и `/api/me` проверяются при запуске; локальный аккаунт имеет `isAdmin=true` и `isSuperAdmin=true`.

## Что в целевой спецификации остаётся дальнейшим развитием

Отдельно от модели ролей описаны второй фактор, свежая проверка личности для критических действий, передача самой платформы с принятием новым владельцем, специальный процесс разрешения конфликта интересов, версионируемые изменения формул рейтинга, редакторы справочников и системных настроек. Эти новые подсистемы в текущую локальную версию не добавлены. Текущие ограничения подтверждения результатов сохранены; новые роли не вводят отдельный процесс разрешения споров.
