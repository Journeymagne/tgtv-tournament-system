# Локальный стенд Windows

Стенд создан 17 сентября 2026 года. PostgreSQL 16.15 запускается напрямую из
Windows-бинарников EDB, Node.js — отдельным фоновым процессом. Docker не нужен.
Сервер и база слушают только `127.0.0.1`.

## Адрес и данные

- Сайт: <http://127.0.0.1:3000>.
- PostgreSQL: `127.0.0.1:55432`, пользователь БД `tgtv`.
- `tgtv_local_demo` — база сайта с демонстрационными данными.
- `tgtv_local_test` — отдельная база автоматических тестов.
- Пароль PostgreSQL и строки подключения находятся в локальном `.env`.

В демонстрационной БД ровно 100 аккаунтов: `admin` и `Player001`–`Player099`.
По просьбе пользователя пароль каждого локального демонстрационного аккаунта
совпадает с его именем для входа, с учётом регистра: `admin` / `admin`,
`Player032` / `Player032`. Это правило используется и при первоначальном
заполнении демонстрационной базы; переменные `LOCAL_DEMO_PASSWORD` и
`LOCAL_DEMO_ADMIN_PASSWORD` больше не используются. Обычная регистрация
пользователей по-прежнему принимает выбранный ими пароль.

Создано 20 команд с разными названиями. В каждой три случайно выбранных игрока,
один из них — лидер. Между командами участники не повторяются: 60 игроков
в командах, 40 аккаунтов без команды (включая `admin`). Все рейтинги начинаются
с 1000; матчи и турниры не создавались.
Составы: `work/local-runtime/demo-roster.json`.

## Запуск и остановка

В PowerShell из корня проекта:

```powershell
.\scripts\start-local.ps1
```

Команда запускает PostgreSQL и сайт в фоне. Повторный запуск использует
уже работающие процессы этого стенда. Остановить оба процесса:

```powershell
.\scripts\stop-local.ps1
```

Данные сохраняются после остановки. Автозапуск при входе в Windows не настроен;
после перезагрузки нужно выполнить `start-local.ps1`.

Скрипты рассчитаны на уже подготовленное локальное окружение. Если оно
переносится на другой компьютер, отдельно потребуются Node.js >=22,
`npm ci`, Windows-бинарники PostgreSQL, инициализированный кластер и `.env`.
Официальный источник бинарников:
[EDB PostgreSQL Binaries](https://productsdl.enterprisedb.com/download-postgresql-binaries).
Скрипты используют короткий Windows-путь для совместимости PostgreSQL
с кириллицей в родительских папках.

## Проверки и повторное наполнение

```powershell
npm test
node scripts/seed-local-demo.js
```

Тесты используют только `TEST_DATABASE_URL`, указывающий на `tgtv_local_test`.
Демонстрационный сайт использует `DATABASE_URL` с `tgtv_local_demo`.
Не менять тестовый URL на базу сайта: тесты очищают свои таблицы.

Скрипт наполнения допускает только `127.0.0.1:55432/tgtv_local_demo`.
При `NODE_ENV=production` он запрещён даже с локальным адресом. Скрипт не
вызывается обычным запуском приложения или механизмом миграций.
Он создаёт данные в пустой базе, а повторный запуск проверяет наполнение,
не добавляя дубликаты и не удаляя существующие записи. После ручного изменения
количества пользователей/команд проверка может завершиться ошибкой — это не
команда сброса стенда.

## Файлы локального окружения

| Путь | Назначение |
| --- | --- |
| `.env` | Локальные настройки и пароли |
| `work/local-runtime/pgsql/` | Бинарники PostgreSQL |
| `data/local-postgres/` | Постоянные данные обеих баз |
| `work/local-runtime/postgres.log` | Журнал PostgreSQL |
| `work/local-runtime/app.log`, `app.err` | Журналы приложения |
| `work/local-runtime/app.pid` | PID процесса приложения |
| `work/local-runtime/demo-roster.json` | Созданные аккаунты и составы команд, без паролей |

`.env`, `work/` и `data/` уже исключены из Git.

## Результаты проверки 17 сентября 2026

- `npm test`: 564 теста прошли, ошибок и пропусков нет.
- Через HTTP проверены главная страница, 100 пользователей, все 20 команд
  и состав каждой, вход администратора и лидера команды, административный API.
- Повторный запуск seed подтвердил прежние числа без добавления записей.
- Выполнены `stop-local.ps1` и `start-local.ps1`; после перезапуска повторно
  проверены доступность сайта, вход и сохранность всех пользователей/команд.
- Применены все 19 миграций. Журнал ошибок приложения после проверки пуст.
