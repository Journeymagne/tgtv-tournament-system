# Telegram: первый этап — бот Турнирной системы

Бот использует существующий Node.js-сервер, PostgreSQL, аккаунты и правила доступа
Турнирной системы. Отдельный backend и Mini App для первого этапа не нужны.
Остальные сервисы Companion в бота не входят.

## Что реализовано

- Привязка одного Telegram к одному аккаунту сайта: профиль → ссылка в бота →
  Start → подтверждение выбранного Telegram в профиле. Ссылка одноразовая,
  действует 10 минут; в базе хранится только её хеш.
- `/start`, `/help`, `/games`, `/tournaments`, `/profile`, `/settings`, `/stop`.
  Главное меню и настройки доступны кнопками. Русский и английский языки.
- Активные игры, командные пары, ближайшие турниры, рейтинг TTS и IRL.
- Уведомления о вызове, приглашении в команду, начале турнира, одиночной
  и командной паре, результате, который пользователь вправе подтвердить.
- Настройки по категориям и общая пауза; отвязка через сайт или `/unlink`.
- Переход из уведомления сразу к соответствующему матчу, приглашению или турниру.
  Регистрация, ввод/подтверждение результатов, работа капитана и управление
  турниром на этом этапе выполняются в существующем интерфейсе сайта.

Бот работает в личных сообщениях. Сайт может быть закрыт: сервер сам сохраняет
события и отправляет уведомления. Вызовы и приглашения здесь относятся к
Турнирной системе, а не к другим разделам Companion.

## Действия владельца в BotFather

1. Открыть официальный [@BotFather](https://t.me/BotFather) и отправить `/newbot`.
2. Указать имя, например `Thunderground Tournaments`, и свободный username,
   заканчивающийся на `bot`, например `ThundergroundTournamentsBot`.
3. Сохранить выданный токен в `TELEGRAM_BOT_TOKEN` приватного `.env` работающего
   сервера. Не помещать его в Git, скриншоты, задачи или переписку.
4. При желании через `/setdescription` задать:
   `Турниры Kill Team: ваши пары, матчи, рейтинг и уведомления о результатах.`
5. Через `/setjoingroups` можно запретить добавление в группы. Privacy Mode
   можно оставить включённым. Mini App, Web Login и домен в BotFather на этом
   этапе не настраиваются.

Команды меню устанавливает скрипт `npm run telegram:setup`, поэтому вручную
вводить их через `/setcommands` не требуется. Аватар и короткое описание
можно добавить позже через `/setuserpic` и `/setabouttext`.

## Рекомендуемый запуск: polling

Для первого запуска достаточно постоянно работающего сервера Турнирной системы
с исходящим HTTPS-доступом к `api.telegram.org`. Публичный входящий адрес для
самого бота не нужен. Игрокам нужен доступный адрес сайта, чтобы открывать матчи.

В приватном `.env` **того экземпляра приложения, который будет работать с ботом**:

```dotenv
TELEGRAM_MODE=polling
TELEGRAM_BOT_USERNAME=ThundergroundTournamentsBot
TELEGRAM_BOT_TOKEN=<токен из BotFather>
SITE_URL=https://ktcompanion.ru
```

Username указывается без `@`; пример нужно заменить на фактический.
`SITE_URL` — origin без пути `/tournament`, параметров и фрагмента. Все ссылки
бота ограничены этим origin и маршрутами Турнирной системы. Для локальной
разработки разрешён HTTP на localhost; для рабочего сервера требуется HTTPS.

Существующие параметры `DATABASE_URL`, `PGSSL`, `HOST`, `PORT`,
`COMPANION_ORIGIN` и настройки сервера сохраняют своё назначение.
Локальная проверка должна использовать отдельную локальную базу.
Не запускайте локальный и рабочий polling одновременно с одним токеном.

Из корня проекта:

```powershell
npm run telegram:setup
npm start
```

На уже работающем сервере вместо второго параллельного `npm start` нужно
перезапустить существующий сервис через его менеджер процессов.
Миграция **057_telegram_bot** применяется обычным механизмом запуска.
Скрипт проверяет соответствие токена username, устанавливает русские/английские
команды и режим кнопки меню, снимает webhook без удаления ожидающих updates.
Сервер получает updates, отвечает на команды и обрабатывает очередь сообщений.

Worker фиксирует ID бота в `telegram_state`: случайная подмена токена ботом с
другой идентичностью останавливает отправку. Замена токена через BotFather
для того же бота не требует сброса привязок. Переезд на совершенно другого бота
требует отдельной миграции привязок; нельзя просто заменить username и токен.

## Альтернативный запуск: webhook

Webhook нужен только при соответствующей схеме хостинга. Приложение всё равно
должно постоянно работать для отправки очереди.

```dotenv
TELEGRAM_MODE=webhook
TELEGRAM_WEBHOOK_SECRET=<случайная строка не короче 32 символов>
```

Остальные параметры совпадают с polling. Секрет можно сгенерировать локально
через `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"`
и сохранить только в приватном `.env`.
Прокси должен пропускать HTTPS POST на `/api/telegram/webhook` и заголовок
`X-Telegram-Bot-Api-Secret-Token`. Выполнить `npm run telegram:setup`, затем
перезапустить приложение. Без правильного секрета endpoint возвращает 403.
В других режимах endpoint возвращает 404.

## Подключение игрока

1. Войти в существующий аккаунт сайта; открыть `/tournament#/profile`.
2. В карточке Telegram нажать «Подключить Telegram», затем «Открыть Telegram».
3. В боте нажать Start, вернуться в профиль и подтвердить **свой** аккаунт.
4. Проверить `/profile`, `/games`, `/tournaments`, выбрать категории в `/settings`.

Само открытие ссылки ещё не связывает аккаунты: завершить привязку может только
авторизованный владелец профиля. Веб-изменения защищены проверками сессии,
текущего аккаунта, Origin и CSRF. Имя пользователя Telegram не используется
для авторизации — привязка хранит числовой Telegram ID.

`/stop` останавливает уведомления; включение доступно через `/settings`.
После блокировки бота в Telegram доставка прекращается. Для возобновления
нужно разблокировать бота и отправить `/start`. Отвязка удаляет связь и её
ожидающие сообщения, сохраняя аккаунт, результаты и рейтинг сайта.

## Очередь и ограничения первого этапа

События PostgreSQL создаются в транзакции с изменением матча/турнира. Worker
выбирает актуальные события, проверяет получателя и настройки, сохраняет
исходящее сообщение. Перед отправкой снова проверяются права и актуальность:
отменённые приглашения, завершённые игры и уже подтверждённые результаты
не должны отправляться из старой очереди.

Повторные Telegram updates и одинаковые уведомления имеют ключи дедупликации.
Ошибки сети и лимиты Telegram приводят к повторным попыткам с задержкой;
403 помечает чат заблокированным. В один чат отправляется не более одного
сообщения в секунду; один worker отправляет глобально последовательно.
Если Telegram принял сообщение, но сетевой ответ потерялся, повтор при retry
всё же возможен: Bot API не предоставляет ключ идемпотентности `sendMessage`.

История до привязки не рассылается; текущие игры остаются доступны по `/games`.
Для отключённых категорий события не накапливаются «на потом».
Команда показывает до пяти индивидуальных игр и трёх командных пар, со ссылкой
на полный список сайта. Старые терминальные записи очереди очищаются через
30 дней, обработанные updates — через 7 дней, просроченные ссылки — раз в час.

Первая версия рассчитывает на один постоянно работающий экземпляр сервиса.
Poller защищён блокировкой PostgreSQL; очередь использует блокировки и аренду
заданий. Массовый fan-out на тысячи привязок и глобальные лимиты нескольких
worker требуют отдельной оптимизации перед таким масштабированием.

## Локальная проверка без Telegram

```dotenv
TELEGRAM_MODE=local
TELEGRAM_BOT_USERNAME=TGTVLocalPreviewBot
SITE_URL=http://127.0.0.1:3021
HOST=127.0.0.1
NODE_ENV=development
```

Этот режим не обращается к Telegram: исходящие payload сохраняются в
игнорируемой папке `work/telegram/*.json`. Входящие демонстрационные updates
можно передавать локальным скриптом в `handleUpdate` внутри транзакции;
публичного endpoint для имитации updates нет. Режим разрешён только на loopback
в development. Ссылка на демонстрационный username не является рабочим ботом.
Для реальной приёмки нужны настоящий токен, `polling` и `telegram:setup`.

При разработке проверены локальные страницы/API, миграция, привязка и запреты
CSRF/Origin/чужого аккаунта, повторная обработка update, одиночные и командные
пары, запрос результата, `/stop`, фильтрация категорий и карточка профиля
в отдельном браузере. Тестовые наборы репозитория не запускались согласно
AGENTS.md. Проверка настоящего Bot API остаётся после выдачи токена владельцем.

## Приёмка настоящего бота

После настройки проверить на двух тестовых аккаунтах: привязку; правильный
профиль; создание вызова; публикацию пары; уведомление второму участнику после
отправки результата; отключение категории; `/stop`; отвязку. Проверить доставку
при закрытом сайте и после перезапуска процесса. Для командных турниров также
проверить получателей-капитанов и разрешения подтверждения результатов.

На втором этапе Mini App сможет использовать те же аккаунты, данные и доменные
правила. Потребуются проверка Telegram `initData` и мобильные экраны действий;
текущая веб-сессия сама по себе не заменяет авторизацию Mini App.

Официальные источники: [BotFather и создание бота](https://core.telegram.org/bots/features#botfather),
[Bot API](https://core.telegram.org/bots/api), [FAQ о доставке и лимитах](https://core.telegram.org/bots/faq).
