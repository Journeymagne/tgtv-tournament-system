# UI Kit — автономный каталог

Каталог сохранён в [`design/ui-kit/index.html`](../design/ui-kit/index.html).
Откройте этот файл в браузере. Сервер, база данных и авторизация не требуются.
Каталог не подключён к сервисам и не публикуется через маршруты приложения.

Аудит всех сервисов от 22 октября 2026 года сохранён рядом с каталогом:
[`design/ui-kit/audit/2026-10-22/index.html`](../design/ui-kit/audit/2026-10-22/index.html).
В отчёте — расхождения, замеры, скриншоты и границы проверки. Код сервисов
в ходе аудита не менялся.

После аудита общие элементы сервисов приведены к этому стандарту:
единый блок профиля, размеры кнопок и уведомления. Сам каталог остаётся
автономным. Источник общих токенов — `public/companion-tokens.css`;
`design/ui-kit/tokens.css` и `services/combat-lab/src/companion-tokens.css`
хранят идентичные копии для автономного использования и сборки.
Правила размеров описаны в [button-standard.md](button-standard.md).
Результаты повторной проверки — в [отчёте об исправлениях](../design/ui-kit/audit/2026-10-22/fixes.html).

Это заготовка для будущих подсервисов: блок аккаунта, кнопки, аватары,
MMR, переключатели языка и темы, иконки и счётчики уведомлений.
Примеры показывают игрока, гостя, длинное имя, отсутствие рейтинга и 99+.
Настройки темы и языка действуют только внутри открытого каталога.
Демонстрационные действия не вызывают API и не меняют аккаунты.

## Файлы

- `design/ui-kit/index.html` — каталог с примерами и шаблоном использования.
- `design/ui-kit/tokens.css` — самостоятельная копия палитры и размеров.
- `design/ui-kit/components.js` — DOM-компоненты `KTComponents` без зависимостей.
- `design/ui-kit/components.css` — стили компонентов и мобильная раскладка.
- `design/ui-kit/catalog.js`, `catalog.css` — поведение и оформление примеров.
- `design/ui-kit/icon.png` — локальное изображение для демонстрации аватара.

## Использование в будущем

Когда потребуется подключение, перенесите `tokens.css`, `components.css`
и `components.js` в новый сервис. Загрузите их в этом порядке; компонентный
скрипт должен выполниться до кода, который вызывает `KTComponents`.
Пример ниже размещается в скрипте будущего сервиса:

```js
const bar = KTComponents.accountBar({
  user: { name: 'Player', rating: 1123 }, // null для гостя
  locale: 'ru', theme: 'dark',
  profileHref: '#profile', loginHref: '#login',
  onTheme: value => { /* обновить тему будущего сервиса */ },
  onLocale: value => { /* обновить язык будущего сервиса */ },
  onLogout: async () => { /* выход средствами будущего сервиса */ }
});
document.querySelector('[data-account-bar]').append(bar.element);

const bell = KTComponents.notificationButton({ count: 3, locale: 'ru' });
bar.notifications.append(bell.element);
bell.setCount(128, 'ru');
bar.setUser({ name: 'Another player', rating: 1200 });
bar.setAppearance({ locale: 'en', theme: 'light' });
```

В будущем интеграционный код отвечает за сессию, API, навигацию и сохранение
настроек. Сами компоненты не отправляют сетевые запросы и не подписываются
на глобальные события. Дополнительные примитивы: `button()`, `avatar()`,
`rating()`, `notificationButton()`.

Аватар без изображения или с ошибкой загрузки показывает инициалы. Неизвестный
MMR скрывается; `ratings.combined` имеет приоритет перед `rating`. Нулевой
счётчик уведомлений скрыт, значения больше 99 показываются как `99+`.
Высота кнопок — 40 px, на мобильном экране — 44 px. В каталоге можно проверить
обе темы, клавиатурный фокус и переносы на узком экране.
