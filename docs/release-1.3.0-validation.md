# KT Companion 1.3.0 validation

Release date: 17 October 2026. The release includes the tournament changes in
the working copy and all main commits after v1.2.0. Know Thy Kill Team remains
unreleased; its files and all shared application hooks are excluded.

## Scope and packaging

- Standings and tournament statistics: search, faction/classification filters,
  minimum game count, sortable columns and retained navigation/filter state.
- Repeated opponent/team and IRL table warnings, including two confirmations
  before starting affected games and cancellation without a write.
- Swiss cross-bracket rematch avoidance and stable eligible preview byes.
- Previously merged venue-address, KT2024 melee and Linux release preparation
  updates after the original v1.2.0 tag.
- Application, Combat Lab, both lockfiles and client asset markers use 1.3.0.
  Dependency graphs are unchanged. There are no new environment variables.
- Latest migration is 055_tournament_venue_address, already present in main;
  it applies when upgrading from the original v1.2.0 tag. Migration 056,
  training routes, questions, progression, achievements and UI are absent.

## Automated checks before merge into main

The full serial run executed 1,071 tests against the newly created local
PostgreSQL database tgtv_release_130_test_20261017 at 127.0.0.1:55444.
All 364 integration tests passed. One of 707 unit tests initially failed:
the public-page script-order expectation did not include the new pairing
warning and table bundles. Its expectation was updated to require both
bundles before app.js. The complete unit suite was then repeated: 707 passed,
zero failed or skipped. No application code changed after the integration run.

JavaScript syntax and Git whitespace checks passed. Combat Lab production
compilation completed successfully with existing CRA/Browserslist warnings.
No dependency updates were made to suppress those toolchain warnings.

## Browser and local runtime checks

The existing browser inspection scripts ran against the release's actual
client files with deterministic fixtures. Checks covered ascending/descending
numeric sorting, player/roster search, faction/classification/minimum-games
filters, empty and reset states, filter retention after refresh, and individual
and team pairing warnings. Cancelling confirmation produced zero commits;
accepting both confirmations produced one. No page errors or document overflow
were reported at mobile width 390px. Desktop and mobile screenshots were
visually inspected in dark and light themes.

The application also ran at 127.0.0.1:3013 against a separate newly created
tgtv_release_130_preview database. A normal LocalPreviewAdmin session and an
ignored loopback-only helper supplied administrator autologin. The real browser
displayed administrator controls. Home, tournament, /api/me, /combat and
/combat/api/health returned 200; user.isAdmin and buildReady were true.
/training and /api/training/questions returned 404. No training scripts or
training service card were present.

Evidence remains in ignored work/ files: release-1.3.0-tests.log,
release-1.3.0-unit-final.log, release-1.3.0-smoke.json and the isolated
runtime's tournament-tables-qa/ and pairing-warnings-qa/ directories.
Production and user databases were not used for these checks.

## Publication and deployment

The release is published as v1.3.0 with a source ZIP generated by git archive
from the exact tagged commit. Local configuration, sessions, databases, work
files, dependencies and training module sources are excluded. Source releases
install/build through the normal deployment workflow.

Publishing main, the tag and GitHub Release does not deploy the Linux host.
The production PM2 switch was not performed or verified during this release.
Follow docs/deployment.md and run bash update_tgtv-ts.sh production on the host.
