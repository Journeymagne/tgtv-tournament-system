# Квоты и защита от исчерпания ресурсов

Квоты одинаковы для игроков, организаторов и администраторов. Суперадминистратор
может повысить отдельные квоты аккаунта в разделе **Администрирование → Игроки →
Управление → Квоты**. Изменение требует причины, проверяет текущую версию настроек
и записывается в административный журнал. Пустое поле возвращает стандарт.
Безлимитных значений нет; допустимый максимум каждого поля сообщает API.

| Ресурс | Стандартная квота |
| --- | --- |
| Регистрация | 10 успешных регистраций с IP в час, 50 в сутки |
| Сессии | 10 активных; новый вход закрывает самые старые |
| Успешные входы | 5 в минуту, 30 в час на аккаунт |
| Studio | 50 проектов, 1 GiB суммарно для черновиков, опубликованных копий и TTS |
| TTS | 512 MiB внутри общей квоты Studio; 20 экспортов на проект |
| Создание Studio | 10 проектов в сутки |
| Публикация Studio | 10 в час |
| Сохранения Studio | 30 в минуту, 600 в час |
| Создание экспорта TTS | 10 в час |
| Игровые команды | Руководство 5 активными командами; 2 новых команды в сутки |
| Приглашения | 20 в сутки; одному получателю — 3 в сутки |
| Вызовы | 20 в сутки, одному получателю — 3; 10 ожидающих исходящих |
| Турниры организатора | 10 незавершённых, 2 новых в сутки |
| Индивидуальный Swiss | 256 записей участников, включая выбывших и удалённых; 20 раундов |
| Массовое добавление участников | 100 за запрос |
| Столы | 256 на турнир; ограничения конкретного формата сохраняются |
| Обратная связь | 3 обращения в сутки, 10 открытых |
| Тренировки | 10 новых сессий в час, 50 в сутки; ответы не расходуют этот бюджет |
| FAQ и достижения | По 20 новых карточек/достижений в сутки; общий бюджет 60 правок в час |

Источник значений — `src/resources/policy.js`. Окна бюджета начинаются с первой
успешной операции и сбрасываются после истечения соответствующего интервала,
а не в полночь. Удаление, отмена или архивирование не возвращают бюджет создания.
Неуспешная транзакция бюджет не расходует. Отдельные ограничения попыток запросов
действуют до разбора тела и обращения к базе.

Проверка количества и запись выполняются в одной транзакции. Проверки Studio и
квот владения сериализуются по аккаунту; лимиты частоты хранятся в PostgreSQL и
сохраняются после перезапуска процессов. Передача команды/турнира и восстановление
архивной команды проверяют квоту нового владельца. Объём Studio учитывает JSONB
в несжатом текстовом представлении, обе копии проекта и файлы/манифесты TTS.

Существующие данные не удаляются при миграции или снижении индивидуальной квоты.
Чтение, удаление и уменьшение объёма разрешены. Блокируется увеличение ресурса,
которое превышает квоту. Старые завершённые турниры не занимают квоту незавершённых.
Истёкшие временные счётчики и сессии удаляются небольшими порциями; история объектов не
очищается автоматически. Новые записи аудита содержат хеши вложенных изображений
и PDF вместо повторных копий файлов; очень большие снимки ограничены по размеру.

## Технические ограничения

Эти ограничения суперадминистратор через квоты не отключает:

- Существующий максимум запроса Studio/TTS — 100 MiB; у остальных маршрутов свои меньшие пределы.
- До 64 одновременно обрабатываемых запросов API на процесс и 128 MiB зарезервированных
  тел запросов. Резерв берётся до чтения тела по Content-Length; загрузка без
  указанного размера резервирует полный разрешённый размер маршрута.
- 1200 попыток запросов в минуту на IP на процесс; 120 записей в минуту на аккаунт.
  Таблица оперативных счётчиков ограничена 10 000 ключами.
- Большой JSON, проверка больших проектов Studio, PNG/TTS и паринг следующих раундов
  Swiss выполняются в worker thread: по умолчанию одна задача без очереди, таймаут
  15 секунд, heap worker до 512 MiB. Совокупный распакованный объём PNG в одном TTS
  наборе ограничен 512 MiB. Heap не является пределом всей памяти процесса.
- Чтение тела — 30 секунд, для больших загрузок — 90 секунд. Отклонённые загрузки
  продолжают занимать слот до окончания чтения или закрытия соединения.
- Запрос PostgreSQL — до 15 секунд; ожидание блокировки — 3 секунды; простаивающая
  транзакция — 30 секунд. Миграции временно отключают эти таймауты.
- Глобальные списки пользователей, команд в рейтинге/администрировании, турниров,
  обратной связи, FAQ и достижений выдаются страницами. Параметры: `page`, `limit`
  (по умолчанию 20, максимум 100); ответ содержит `pagination`.

Бизнес-квоты общие для сервисов благодаря PostgreSQL. Ограничения памяти, worker
threads и попыток запросов локальны для процесса. При нескольких репликах внешний
прокси должен ограничивать общий поток и размер запросов. `TRUST_PROXY` включается
только за доверенным прокси, который перезаписывает заголовки клиента.

## API и установка

- `GET /api/account/quotas` — свои действующие квоты и использование.
- `GET /api/admin/users/:id/quotas` — просмотр суперадминистратором.
- `PATCH /api/admin/users/:id/quotas` — `{ "revision": 0, "overrides": { "teamsActive": 10 }, "reason": "Организация лиги" }`.
- Превышение количества/объёма: HTTP 409 с `quota.key`, `quota.limit`, `quota.usage`.
- Превышение частоты или занятый обработчик: HTTP 429 с `Retry-After`.

Перед запуском разделённых сервисов выполнить `npm run db:migrate` учётной записью
владельца схем. Нужна миграция **067_resource_quotas**; она измеряет объём существующих
проектов, поэтому для большой базы нужно предусмотренное окно миграции. При новом
развёртывании после миграций выполнить обычное provision сервисных ролей.
Применение миграции к рабочей базе и развёртывание — отдельный шаг релиза.

Параметры процесса: `API_MAX_INFLIGHT=64`, `UPLOAD_MEMORY_BUDGET_MIB=128`,
`RESOURCE_WORKERS=1` (1–4). Менять их следует по измерениям памяти и задержек сервера.

Целевые проверки: `node --test test/unit/resource-guards.test.js
test/integration/resource-quotas.test.js` с `TEST_DATABASE_URL`, указывающим на
отдельную тестовую PostgreSQL. Нагрузочные атаки на рабочий сайт не выполняются.
