# Хранение ачивок и импорт из старого бота

## Схема

Используется существующая PostgreSQL проекта. Каталог и выдачи хранятся отдельно.

| Таблица / поле | Назначение |
| --- | --- |
| `achievements.id` | Внутренний ID сайта, генерируется независимо от старого бота |
| `name`, `description` | Название и описание без изменения исходного текста |
| `emoji` | Полный Unicode-эмодзи, включая модификаторы и составные символы |
| `image_data` | Необязательная загруженная картинка; при её отсутствии показывается эмодзи |
| `kind` | `player` — личная ачивка, `team` — командная |
| `category` | `achievement` — Ачивки, `title` — Hall Of Fame; независимо от типа получателя |
| `tournament_number` | Номер турнира для сортировки титулов по убыванию; извлекается из названия, поддерживаются римские числа |
| `deleted_at` | Удаление из каталога и профилей с сохранением истории; повторная публикация итогов не восстанавливает награду |
| `achievement_award_members` | Необязательный состав при командной выдаче: ссылка на игрока и снимок его имени |
| `legacy_source`, `legacy_id` | Источник `achievement-bot` и старый числовой ID; уникальная пара защищает от повторного импорта |
| `tournament_id`, `place` | Только для автоматически созданных наград за места 1–3; у старого каталога не заполнены |
| `achievement_awards` | Связь ачивки с игроком или командой, дата выдачи и администратор |

В записи выдачи заполнен ровно один получатель: `user_id` или `team_id`.
Уникальные пары «ачивка + игрок» и «ачивка + команда» исключают дубли выдачи.
Старый ID не заменяет внутренний: это сохраняет существующие ссылки и выдачи
и позволяет позднее сопоставить экспорт получателей со старым каталогом.

## Начальные данные

Источник: `achievements_202607081738.csv`, предоставленный пользователем.
Все 39 записей сохранены в `src/db/seeds/legacy-achievements.json`.
Миграция `024_legacy_achievements` добавляет поля происхождения и заполняет каталог
при запуске приложения, в одной транзакции стандартного механизма миграций.
Для развёртывания исходный файл из папки Downloads больше не нужен.

Названия, описания и эмодзи перенесены дословно. Все записи относятся к личным
ачивкам: источник не содержит признака типа, а упоминания команд описывают
участие игрока в составе команды. Эти исторические награды доступны для ручной
выдачи администратором и не связаны с автоматическими медалями новых ивентов.

CSV не содержит получателей или дат выдачи: импорт не создаёт записей
`achievement_awards`. Для переноса прежних выдач потребуется отдельный экспорт
и сопоставление старых пользователей с аккаунтами сайта.

Повторное применение миграции не создаёт дубликатов и не перезаписывает
изменённые на сайте данные. Существующие ачивки, их ID, картинки и выдачи
сохраняются. В резервную копию входят каталог, выдачи и составы выдач.

Миграция `026_achievement_titles` переносит 17 наград победителей старого каталога
в Hall Of Fame, сохраняя ID и выдачи. Автоматические медали новых ивентов также
относятся к Hall Of Fame. В Ачивках сортировка по дате добавления и ID, новые
сверху; у титулов приоритет имеет номер турнира, записи без номера идут после
нумерованных. Состав можно выбрать из текущих и бывших участников команды;
выдача остаётся командной и не создаёт отдельных личных наград участникам.

## Перенос в релизе 3.0.0

При подготовке релиза каталог сверен с локальной демонстрационной БД:
39 действующих записей совпадают с seed по названию, описанию и эмодзи;
17 из них относятся к Hall Of Fame после миграции 026. Отдельный дамп не нужен.

На рабочую БД переносятся определения наград через миграции, а не локальная БД.
Демо-пользователи, команды, турниры, матчи, локальные выдачи и удалённая
тестовая награда не включены в начальный каталог. Миграции сохраняют
существующие данные рабочей БД и не запускают `seed-local-demo.js`.
