# KT Companion — Android и iOS

Нативный клиент турнирной системы на React Native + Expo 58 / TypeScript. Общие аккаунты, турниры и результаты с сайтом; WebView не используется. Серверные проверки доступа остаются обязательными. Код приложения находится в этой папке, исходный сайт не заменён и продакшен не развёрнут автоматически.

## Запуск и сборка

```sh
npm ci
npm start
# При наличии Android SDK / Xcode:
npm run android
npm run ios
# JavaScript bundles для Android/iOS/web, НЕ APK/IPA:
npm run export
```

Для SDK 58 нужен совместимый development client. Не считать наличие Expo Go гарантией совместимости. `npm run build:android` / `npm run build:ios` — конфигурации EAS; сначала нужно связать проект с Expo-аккаунтом (`npx eas-cli init`) и настроить credentials. Скрипты используют `npx eas-cli`, отдельная глобальная установка не нужна.

CI `Mobile` собирает TypeScript, проверяет токены UI-кита и API transport, экспортирует три пакета JS. Нативные jobs создают тестовый Android release APK (debug signing, не магазинный ключ) и unsigned iOS Simulator `.app`. Simulator `.app` не устанавливается на iPhone. Для TestFlight / устройств нужны Apple Developer Team, App ID и подпись; для Google Play — собственный upload key и аккаунт Play Console. Автопубликации в магазины нет.

## API и настройки

По умолчанию HTTPS API `https://ktcompanion.ru`. Для европейской сборки задать `EXPO_PUBLIC_API_URL=https://killteamcompanion.com` перед сборкой. Эта переменная публичная и не должна содержать секретов. Переключения домена на лету и переноса cookie между доменами нет. Пароли и session cookie не сохраняются в JS; сессию обслуживает нативный HTTP cookie store. На устройствах обязательно проверить её сохранение после перезапуска и logout.

React Native Web используется для проверки геометрии. Сервер не разрешает произвольный cross-origin браузерный доступ: production CORS ради превью не ослаблен. Не вводить production credentials в локальные сторонние прокси. Визуальные fixtures из review не являются настоящим аккаунтом и не попадают в release entry.

Язык и тема сохраняются локально. При отсутствии явного языка приложения берётся язык связанного бота; иначе — поддерживаемый язык устройства. Ручной выбор не меняет настройку бота. Уведомления внутри приложения загружаются из реального API; push-доставка APNs/FCM ещё требует отдельной инфраструктуры и provision.

## Дизайн и адаптация

[Матрица устройств и UI Kit](docs/responsive.md), [контракты API](docs/api-contracts.md), [покрытие экранов](docs/screen-coverage.md).

Пять смартфонов из годового рейтинга продаж, три планшета, дополнительные граничные ширины. Safe-area, системный Back, клавиатура, прокрутка, переносы, боковая навигация от 600 и широкие формы от 840. RU/EN и обе темы. Цвета генерируются `npm run tokens` из канонического файла. Кнопки используют собственное статическое начертание Inter 650; лицензия рядом со шрифтами.

## Границы проверки

Успешная сборка не подтверждает работу на устройстве. Перед распространением нужны нативные проверки входа/выхода и cookies, текст 200%, VoiceOver/TalkBack, поворот и split view, клавиатура, медленная сеть, отправка/подтверждение результата двумя реальными локальными тестовыми аккаунтами. Тестовые действия не выполняются на production турнирах. Native integration reports должны хранить точную версию сборки и устройство.

По AGENTS.md автотесты запускаются в GitHub Actions. Локальная компиляция, экспорт и визуальная проверка допустимы. Закрывающая оценка и артефакты текущего прохода — в `review/`, когда проверка завершена.
